# inkdeus

A browser-based editor that turns one color illustration into a black-and-white, manga-style page
(line art + solid blacks + layered hatching) with hand-tunable sliders. All rendering runs in WebGL2,
so the preview and the exported PNG are the same pixels.

## これは何か

カラーのイラスト1枚を、白黒の漫画原稿風（線画＋ベタ＋ハッチングの重ねがけ）に手で調整して書き出すエディタです。

- 描画はすべてブラウザの WebGL2。プレビューと書き出しは同じ結果になります。
- トーンは「層」を重ねて作ります。各層は「平滑化した輝度がしきい値未満の所」に平行線を引くので、
  暗い所ほど多くの層が重なり、影の中にも段階的な陰影が出ます。
- 人物マスク（白=人物の PNG）があれば、人物と背景で別々の設定（明るさ補正・ベタ・層）を持てます。背景を「白」「線だけ」にもできます。
- 部分マスク（髪・肌・服など）があれば、部分ごとに別の設定を持てます（「髪は真っ黒のベタに、肌は白に近く」など）。
- 仕上げに、画面の上で**消しゴム**（層ごと・ベタ・線画・すべて）と**ペン**（黒インク・白の修正液）を使えます。
- 稼働中のエディタを外のコマンド（`inkdeus ctl`）から操作でき、変更は開いている画面にすぐ反映されます。
- 書き出した画像を、別プロジェクトの漫画エディタへ持ち込んでページに組めます（後述「漫画の構成」）。
- GPL-3.0-or-later のフリーソフトウェアです。

## 起動

[uv](https://docs.astral.sh/uv/) が必要です。最初に `uv sync` を実行してください。
高画質化（拡大）や人物マスク・部分マスクの作成は inkdeus の外で済ませた物を渡します（inkdeus 自体はそれらを行いません）。

### プロジェクトを作って開く（おすすめ）

プロジェクトは「元画像フォルダ・マスクフォルダ・出力先」をまとめた1つのディレクトリです。
元画像とマスクは既定では**参照するだけ**でコピーしません（`--copy` でプロジェクト内にコピー）。

```bash
uv run inkdeus new <名前> --images <画像フォルダ> [--masks <マスクフォルダ>] [--parts <部分マスクの置き場>] [--copy] [--note "メモ"]
uv run inkdeus open <名前 or プロジェクトのパス> [--port 8770]
uv run inkdeus projects [--json]        # 一覧（画像・マスク・設定済み・書き出し済みの枚数）
```

- 置き場は既定で `~/inkdeus-projects`。環境変数 `INKDEUS_PROJECTS` か、リポジトリ直下の `inkdeus.local.toml`（`inkdeus.local.toml.example` をコピー）の `projects_root` で変えられます。
- プロジェクトの中身は `inkdeus.project.toml`（name / created / source / masks / out / note）と `out/`（設定JSON と書き出した PNG）。
- 既にあるプロジェクトの参照先を変えるときは `inkdeus relink <名前> --images <dir>`（後述「データを守る」）。

表示された URL（既定 `http://127.0.0.1:8770/`）を Chrome / Edge などで開きます。

### 画像フォルダを足す（1つのプロジェクトで複数の画像セットを扱う）

プロジェクトは、画像フォルダ（＝画像セット）をいくつも持てます。作ったときの `--images` / `--masks` が「既定」のフォルダで、あとから足せます。

```bash
uv run inkdeus folders add <プロジェクト> --name <名前> --images <画像フォルダ> [--masks <マスクフォルダ>] [--parts <部分マスクの置き場>] [--note "メモ"]
uv run inkdeus folders list <プロジェクト> [--json]     # 名前・画像数・マスク数・設定済み数・書き出し済み数
uv run inkdeus folders remove <プロジェクト> --name <名前> [--delete-out]
```

- フォルダ名は 1〜32 文字の英数字・かな漢字・`_` `-` で、プロジェクトの中で重複できません（`default` は既定のフォルダの名前なので使えません）。
- 登録内容は `inkdeus.project.toml` の `[[folders]]`（`name` / `images` / `masks` / `parts` / `note`）に書かれます。稼働中に足したフォルダは、画面を読み込み直すと出ます。
- 保存先は、既定のフォルダがこれまでどおり `out/` 直下、足したフォルダが `out/@<名前>/` 以下です（置き方は同じ。別のフォルダに同じ名前の画像があっても混ざりません）。
- `folders remove` は登録を外すだけで、`out/@<名前>/`（設定と書き出した PNG）は残します。`--delete-out` でそれも消します。
- `inkdeus projects` の枚数は全フォルダの合計で、フォルダが複数あるときは内訳も出ます。
- 白黒化の画面では、画像一覧パネルの最上部の「フォルダ」で切り替えます（各フォルダ名に枚数。フォルダが1つだけなら出ません）。切り替えると、そのフォルダで
  最後に開いていた画像（無ければ先頭）が開きます。ヘッダには「プロジェクト名 / フォルダ名」が出て、前後の移動（`[` `]`・◀▶・選択欄）はいまのフォルダの中で動きます。
  最後に開いていたフォルダと画像はブラウザが覚えています。
- 「設定のまだ無い画像を開くと、直前の画像の設定を引き継ぐ」動作は同じフォルダの中だけで働きます（フォルダを切り替えた直後は、そのフォルダで最後に開いていた画像の設定があればそれを引き継ぎます）。
- 「全画像を書き出す」は、いまのフォルダが対象です（「すべてのフォルダ」で全部）。
- 直リンクは `/?folder=<フォルダ名>&image=<画像名>[&version=<バージョン名>]`。

### 部分マスクを登録する（髪・肌・服などを塗り分ける）

部分マスクは、髪・肌・服などの「部分」ごとの領域を示す画像です。inkdeus の外で作った物を、次の置き方で渡します。

```
<部分マスクの置き場>/<部分名>/<画像と同じ名前>.png      例: parts/hair/001.png, parts/skin/001.png, parts/clothes/001.png
```

- 8bit・1チャンネルの PNG で、元画像と同じ縦横、255 = その部分 / 0 = それ以外（ぼかし無し）。同じ画素が複数の部分に属さず、
  人物マスクの内側だけに描かれている物を想定しています。その部分が見つからなかった画像は、全部 0 のファイルで構いません。
  どの部分にも属さない人物の領域は、これまでどおり「人物」の設定で描かれます。
- 部分名は、置き場の直下のフォルダ名から自動で拾います（1〜32 文字の英数字・かな漢字・`_` `-`）。1つの置き場につき 6 部分まで
  （超えた分は名前順で切り捨て）。`person` / `background` / `all` は予約された名前で、部分としては使いません（あれば無視して知らせます）。
- 置き場は画像フォルダごとに 1 つ登録できます。作るとき・足すときの `--parts` のほか、あとから登録・確認・解除できます。

```bash
uv run inkdeus parts set <プロジェクト> [--folder <フォルダ名>] --path <部分マスクの置き場>
uv run inkdeus parts list <プロジェクト> [--folder <フォルダ名>] [--json]    # 部分名と、マスクのある画像の数
uv run inkdeus parts unset <プロジェクト> [--folder <フォルダ名>]             # 登録を外す（置き場の中身には触らない）
```

- 登録内容は `inkdeus.project.toml` に、既定のフォルダは `parts = "<dir>"`、足したフォルダは `[[folders]]` の中の `parts = "<dir>"` として書かれます。
  参照するだけで、`--copy` でもコピーしません。稼働中に登録した分は、画面を読み込み直すと出ます。
- 使い方は「操作の要点」の「部分ごとの塗り分け」を参照してください。

### プロジェクトなしで直接開く

```bash
uv run inkdeus run <画像ファイル or 画像フォルダ> [--mask-dir DIR] [--parts-dir DIR] [--out-dir DIR] [--port 8770] [--host 127.0.0.1]
                    [--add <名前>=<画像フォルダ>[,<マスクフォルダ>[,<部分マスクの置き場>]]]...
```

`inkdeus <実在するパス>` は `run` の省略形です。

- `--mask-dir`: `<画像と同じ名前>.png` を人物マスクとして読みます（8bit、白=人物）。
- `--parts-dir`: 部分マスクの置き場（`<DIR>/<部分名>/<画像と同じ名前>.png`。上の節を参照）。
- `--out-dir`: 書き出し先（既定は `<入力フォルダ>/inkdeus_out`）。`<名前>.png` と、設定の `<名前>.inkdeus.json` が入ります。
- `--add`: 画像フォルダを足します（複数可）。そのフォルダの保存先は `<出力先>/@<名前>/` です。
- 設定は変更のたびに画像ごとに自動保存されます。入力画像は書き換えません。

サーバは静的ファイルの配信とファイルの読み書き（と後述の外部操作の中継）だけを行い、描画には関わりません。

### サーバなし

`web/` を任意の静的サーバで配信すればそのまま動きます（ES Modules のため `file://` 直開きは不可）。

```bash
python3 -m http.server 8000 --directory web
```

画像・マスク・設定JSON はドラッグ＆ドロップかボタンで読み込み、書き出しと設定の保存はダウンロードになります。
ファイル名に `mask` を含む画像はマスクとして扱います。

### 試してみる

```bash
uv run python tests/synth.py demo_images
uv run inkdeus run demo_images/images --mask-dir demo_images/masks
```

## 操作の要点

- プレビュー: ホイールで拡大縮小、ドラッグで移動、「全体表示」「100%」。
  スペースキー（または「元画像」ボタン、`O` キー）を押している間は元画像を表示。「比較」で左右分割（仕切りをドラッグ）。
  消しゴム・ペンを使っている間は、ドラッグは筆になり、スペースキーは「押している間だけ移動」になります（後述）。
- 画像の一覧: 左端の「画像」パネルに全画像のサムネイルが並び、押すとその画像を開きます。名前と状態（未設定 / 未書き出し / 書き出しが古い）で絞り込め、
  各サムネイルに「設定」「書出」「古い」「マスク無」の印が付きます。サムネイルは「元画像 / 白黒版」を切り替えられ、右端のドラッグで幅を変えられます。
  `[` と `]` で前後の画像へ移ります（絞り込み中はその結果の中で。消しゴム・ペンを使っている間は、筆の太さの変更になります）。
- スライダー: 数値欄に直接入力できます。ラベルかスライダーをダブルクリックで既定値に戻ります。
- 取り消し / やり直し: Ctrl+Z / Ctrl+Y。スライダーなどの設定の変更と、消しゴム・ペンの1筆が、行った順に戻ります。
- トーン: 「人物」「背景」のタブで、領域ごとに 明るさ補正・ベタ・層 を持てます（マスクが無い画像は全体が人物扱い）。
  背景は最初は人物と同じ設定で描かれ、「背景だけ別の設定にする」で切り離せます。背景が暗くて黒だらけになる画像は、背景の明るさ補正を上げると救えます。
- 層: 追加・複製・削除・並べ替え・表示のオン/オフ・ソロ表示。名前付きスタイル（重ねがけ4段、単層の細ハッチ、線画のみ、ベタ、白抜き など）を領域ごとに適用できます。
- 各タブの「この領域を強調表示」を押している間、そのタブの領域が色つきで重なって見えます（マスクの出来を確かめるための物で、書き出しには入りません）。
  プレビューを **Alt+クリック**すると、その場所の領域（人物 / 背景 / 部分）のタブへ切り替わります。
- 長さの値は「基準px」です。実際の描画では `unit`（既定 = 画像の幅 / 1280）倍されるので、高解像度の画像でも同じ見た目になります。
- 「PNG を書き出す」でフル解像度の 8bit グレースケール PNG を保存します（「純2値」で白と黒だけ）。
- 「変更を自動で書き出す（漫画の画面へ反映）」（既定オン）の間は、設定を変えて 1.5 秒ほど置くと PNG が自動で保存されます。
  白黒版がまだ無い画像は、開いた時点で書き出されます。ヘッダに「書き出し済み / 書き出し中… / 未反映の変更あり」と出ます。
- 「全画像を書き出す」で、プロジェクトの全画像を順に書き出します。各画像は**その画像に保存済みの設定**で、
  設定がまだ無い画像は**いま画面に出ている設定**で書き出します（その設定がその画像の設定として保存されます）。
  書き出し済みで設定・元画像がその後変わっていない画像は飛ばします（「すべて作り直す」で全部やり直し）。途中で中止できます。
- `http://127.0.0.1:8770/?image=<画像名>` で、その画像を開いた状態で起動します（`&version=<バージョン名>` でバージョンも指定）。

### 部分ごとの塗り分け（「髪はベタに」など）

部分マスク（上の「部分マスクを登録する」）のある画像では、「トーン（ベタ・層）」のタブが「人物 / 背景 / 髪 / 肌 / 服 …」に増えます
（その画像にマスクのある部分だけ。`hair` `skin` `clothes` は「髪」「肌」「服」と出て、ほかの部分名はそのまま出ます）。

- 部分は、最初は**人物と同じ設定**で描かれます（部分マスクがあるだけでは、絵は変わりません）。部分のタブの「この部分だけ別の設定にする」で、
  いまの人物の設定を写して切り離し、その部分だけの 明るさ補正・ベタ・層 を持てます。「人物と同じに戻す」で元に戻ります（背景タブと同じ流儀です）。
- 「人物」の設定は、どの部分にも属さない人物の領域と、人物と同じ設定のままの部分に効きます。
- 名前付きスタイルの **「ベタ」**（`solid-black`）は、その領域を全面ベタ（真っ黒）にします（ベタのしきい値 1・層なし）。
  **「白抜き」**（`blank`）は層もベタも無しにして、線画だけを残します。どちらも人物・背景・部分のどれにも当てられます。
- 髪を黒く塗ると、髪の流れの線がつぶれます。ベタの欄の「**ベタの中の線画を白抜き**」（`solid.lineKnockout`、0〜1）を上げると、
  ベタで塗られた所の線画が白で描かれます（線画を描く設定が切ってあっても働きます。線画を消しゴムで消した所は白くなりません）。
  髪の輪郭のすぐ内側にも線画が出ているので、輪郭に沿って白い縁が出ることがあります。強さと線画の設定（τ・ε）で加減してください。
- 部分の境界は部分マスクそのままです（人物マスクの「広げ/縮め」は、人物と背景の境界にだけ効きます）。
- 消しゴムは、部分の層（層の行をクリックして選ぶ）と部分のベタ（その部分のタブを開いて「ベタ」）にも使えます。
- 部分の設定は画像・バージョンごとの設定JSON に入ります（`regions.<部分名>`）。その画像に無い部分の設定は、無視されますが消えません
  （設定を次の画像へ引き継いだとき、その画像に同じ部分があれば効きます）。
- 部分マスクは 1 枚の「部分の番号の地図」にまとめて GPU に持つので、部分の数で描画が重くなることはほとんどありません
  （1 画素が計算するのは、その画素の領域と背景の高々 2 領域ぶんです）。一度に扱える層の総数は環境の上限から決まり（普通は 64 層）、
  それを超える分の部分は人物と同じ設定で描いて、その旨を知らせます。
- サーバなしで開いたとき（と、この機能が入る前のサーバにつないだとき）は、部分のタブは出ません。

### 部分マスクの手直し（はみ出し・欠けを、画面で塗って直す）

自動で作った部分マスク（髪・肌・服など）や人物マスクのはみ出し・欠けを、画面の上で塗って直せます。
プレビューの上のツールバーの「**部分マスク**」（キー `M`）を使います。

- **対象**を選びます: その画像にマスクのある部分（髪・肌・服…）か、「人物」。既定は、開いているトーンのタブの部分です。
- **塗る**（その部分に加える）/ **消す**（その部分から外す）を `X` で切り替え、なぞります。太さ（`[` `]`）と硬さを変えられます
  （手直しは「加える・外す・触っていない」の 3 値で持つので、硬さは「縁をどこまで塗るか」に効きます）。
  - 部分どうしは排他です。ある部分に塗った所は、ほかの部分から自動で外れます（あとから塗った部分が勝ちます）。
  - 「消す」で外した所は、どの部分でもない人物の領域になり、「人物」の設定で描かれます。
  - 人物の外には塗れません（塗っても、人物の内側になるまで効きません）。人物そのものを直すには、対象に「人物」を選びます:
    「人物に加える / 人物から外す」。人物から外した所は背景になり、そこにあった部分も外れます。
- ツールを使っている間は、対象の領域が色つきで重なって見えます。「線画だけ表示」で、トーンとベタを隠して線画だけを薄く残せます
  （見やすくするための表示で、書き出しには影響しません）。なぞっている最中は筆の跡が出て、離すと結果に置き換わります。
- **元のマスクのファイルは書き換えません**。手直しは「元のマスクに対する上書き」として、画像ごとに
  `<out>/<名前>.maskedit/<部分名 または person>.png` へ保存されます（8bit グレースケール。255 = 加える / 0 = 外す / 128 = 触っていない。
  画像の長辺が 2048 を超えるときは 2048 相当に縮めて持ちます。足した画像フォルダは `<out>/@<フォルダ>/` 以下）。
  **バージョンには依存しません**（同じ元画像の全バージョンで共通）。
- 取り消し / やり直しは、設定の変更・消しゴム・ペンと同じ並びです（1 筆 = 1 回）。「この対象の手直しを取り消す」「全部取り消す」もあります。
  保存は消しゴム・ペンと同じで、筆を置いた直後に変わった所だけがサーバへ送られます。世代バックアップの対象にも入ります
  （「以前の状態に戻す…」で、設定・消しゴムとペンと一緒に戻ります）。
- 手直しは、その画像の**全バージョン**の描画・書き出しに効きます。手直しすると、開いているバージョンは自動で書き出し直され、
  ほかのバージョンの白黒版は「古い」になります（「全画像を書き出す」で作り直せます）。画像一覧には「マスク直」の印が付きます。
- 手直し済みのマスクを、画像と同じ大きさの PNG として書き出せます（外のツールへ戻す用。元のマスクに手直しを合成した結果）:

```bash
uv run inkdeus maskedit list <プロジェクト> [--folder <フォルダ名>] [--json]     # 手直しのある画像と対象
uv run inkdeus maskedit export <プロジェクト> [--folder <フォルダ名>] -o <dir>    # <dir>/person/ と <dir>/<部分名>/ に書き出す
```

  書き出した物は、部分どうしが排他で、人物の内側だけになっています（そのまま `--masks <dir>/person --parts <dir>` として使える形です）。
- `ctl stats` の `maskEdits` に、手直しのある対象（`person` / 部分名）が出ます。
- サーバなしで開いたとき（と、この機能が入る前のサーバにつないだとき）は、このツールは出ません。

### 自分用スタイル（気に入った層の組み合わせに、名前を付けて保存する）

気に入ったベタと層の組み合わせを、名前を付けて保存し、別の画像・別の領域・別のプロジェクトで呼び出せます。

- 各タブ（人物 / 背景 / 部分）の「スタイルを選ぶ…」の一番下の「**いまの設定をスタイルとして保存…**」で、そのタブの領域の設定を保存します。
  名前（1〜32 文字の英数字・かな漢字・`_` `-` `(` `)`。組み込みのスタイルの名前・別名とは重ねられません）、説明、保存先、
  「明るさ補正も含める」かどうかを決めます。
- 保存する中身は、その領域の**ベタと層**です（背景から保存したときは、背景の描き方も）。「明るさ補正も含める」をオンにすると、
  明るさ・コントラスト・ガンマも入り、当てたときにその値になります（オフなら、当てた先の明るさ補正は変わりません）。
  人物と同じ設定で描いている背景・部分から保存すると、実際に描かれている設定（人物の物）が入ります。
- 保存先は 2 つです。**自分用**（全プロジェクト共通）は利用者の設定フォルダの `~/.config/inkdeus/styles.json`
  （環境変数 `INKDEUS_CONFIG` でフォルダを変えられます）、**このプロジェクト**はプロジェクトのフォルダ直下の `styles.json` です。
  同じ名前が両方にあるときは、プロジェクトの物が使われます。
- 保存したスタイルは、「スタイルを選ぶ…」の組み込みの下に「自分用」「このプロジェクト」の見出しで並びます。選ぶと、組み込みのスタイルと同じように
  その領域へ当たります（取り消せます）。背景の描き方が「白」「線だけ」の背景から保存した物は背景向けで、背景のタブにだけ出ます。
- 「**自分用スタイルを管理…**」で、名前の変更・削除・上書き保存（いまのタブの領域の設定で中身を入れ替える）ができます。
- ファイルの形は `{"version": 1, "styles": [{"name", "aliases", "description", "target", "includeLevels", "data", "createdAt", "updatedAt"}]}` で、
  `data` は `solid` / `layers`（と `levels` / `mode`）です。層の id は持ちません（当てるときに新しく振ります）。
  壊れたファイルや使えない項目は読み飛ばして、その旨を一覧に出します。
- サーバなしで開いたとき（と、この機能が入る前のサーバにつないだとき）は、保存・管理の項目は出ません。

### 消しゴムとペン（手で消す・描き足す）

プレビューの上のツールバーで「手のひら」（移動。既定）・「消しゴム」・「ペン」を切り替えます。

- **消しゴム**は、対象を選んでなぞった所だけを消します。
  - 「選択中の層」: 右のパネルで**層の行をクリック**して選んだトーン層（行が強調されます。人物・背景のどちらのタブの層かも区別します。「ソロ」とは別です）
  - 「ベタ」: 開いているタブ（人物 / 背景 / 別の設定にした部分）の側のベタ
  - 「線画」: 線画（背景を「白」にしたときのシルエット線も含みます）
  - 「すべて」: その場所を白にします（トーン・ベタ・線画をまとめて消します。透かしは消えません）
  - 「消す / 戻す」で、消した所をなぞって戻せます。太さ（基準px）・硬さ（1 で縁がくっきり、下げるほど縁がなだらか）・
    強さ（消す量の上限。0.5 なら半分まで薄くなり、同じ所を重ねてなぞってもそれ以上は薄くなりません）を変えられます。
  - 「全部取り消す」（この対象の消しゴムを全部取り消す）で、その対象を元に戻します。消した所のある層・ベタ・線画には「消しあり」の印が付きます。
- **ペン**は、黒インクと白（修正液）で描き足します。合成の最後（透かしの直前）に重なり、後から描いた方が勝ちます。
  太さ・硬さを変えられ、「筆圧で太さ」（既定オン）でペンタブレットの筆圧が太さに効きます（筆圧の無いマウスは一定）。
  「全部消す」で、ペンで描いた物をまとめて消せます。
- ツールを使っている間、プレビューのドラッグは筆です。移動は **スペースを押しながらドラッグ**、または中ボタンのドラッグ・ホイール。
  元画像の表示は `O` キー（または「元画像」ボタン）を押している間です。
- キー: `E` 消しゴム / `B` ペン / `M` 部分マスク / `H` 手のひら / `X` 消す⇔戻す・黒⇔白・塗る⇔消す / `[` `]` 太さ。入力欄にカーソルがあるときは効きません。
- 筆を置いた（ポインタを離した）時点で、変わった所だけがすぐサーバへ送られ、**画像・バージョンごと**に保存されます
  （1 秒ほど後の「全体の保存」を待ちません。別の画像へ移る前と、書き出しの前にも保存します）。
  置き場所は `<out>/<名前>.paint/`（バージョンは `<out>/<名前>@<バージョン>.paint/`、足した画像フォルダは `<out>/@<フォルダ>/` 以下）で、
  対象ごとの PNG（`layer-<層の id>.png` / `solid-person.png` / `solid-background.png` / `solid-<部分名>.png` / `lines.png` / `all.png` / `pen.png`）と目録 `index.json` です。
  消去マスクは 8bit グレースケール（画像の長辺が 2048 を超えるときは 2048 相当に縮めて持ちます）、ペンは原寸の RGB（R = 黒、G = 白）です。
- 「設定のまだ無い画像を開くと、直前の画像の設定を引き継ぐ」ときも、消しゴム・ペンは引き継ぎません。
  バージョンを複製すると描いた物も写り、名前を変えると付いていき、削除すると消えます。
  層を削除するとその層の消しゴムも消えます（取り消すと戻ります）。層の複製には付いてきません。名前付きスタイルを当てると層が入れ替わるので、前の層の消しゴムは効かなくなります（取り消すと戻ります）。
- 「PNG を書き出す」・自動の書き出し・「全画像を書き出す」・統計（`ctl stats`）のどれにも反映されます。描き足したあとは、書き出した白黒版が「古い」扱いになります。
- 取り消し用には、1筆で触った範囲（256px 角のタイル）の画素だけを持ちます。履歴は 200 件・合計 256 MB までで、超えた分は古い物から捨てます。
- サーバなしで開いたとき（と、この機能が入る前のサーバにつないだとき）は保存されず、画面を閉じるか別の画像へ移ると消えます（書き出しには反映されます）。

### バージョン（同じ画像から、設定の違う白黒版を複数作る）

1枚の元画像から、設定の違う白黒版をいくつも作れます（例: 背景を白にした版と、背景もハッチで描いた版）。
漫画の構成の画面では、それぞれを別の素材として使えます。

- ヘッダの「版」の選択欄で切り替えます。最初からあるのが「既定」のバージョンで、一覧の下の「操作」から
  「いまの設定を複製して新しいバージョン」「名前を変える」「削除」を行います（既定のバージョンは削除・改名できません）。
- バージョン名は 1〜32 文字の英数字・かな漢字・`_` `-` です（`@`・空白・パス区切りは使えません）。
- 設定・書き出した PNG・取り消しの履歴はバージョンごとに別です。人物マスクは元画像の物を共有します。
- 保存先は、既定が従来どおり `<out>/<名前>.inkdeus.json` / `<名前>.png`、名前付きが `<out>/<名前>@<バージョン>.inkdeus.json` / `<名前>@<バージョン>.png` です
  （これまでのデータは、そのまま既定のバージョンとして読まれます）。`a@b.png` のように名前に `@` を含む元画像があるときは、
  元画像の名前を優先して読みます（その場合、`a.png` に `b` という名前のバージョンは作れません）。
- 自動・手動の書き出しは、開いているバージョンが対象です。「全画像を書き出す」は全画像の全バージョンを書き出します（「既定のバージョンだけ」で絞れます）。
- 画像一覧のサムネイルと印は既定のバージョンの物で、名前付きのバージョンがあるとその数（`+2` など）が付きます。
- 「設定のまだ無い画像を開くと、直前に開いていた画像の設定を引き継ぐ」動作は、既定のバージョンだけに働きます。

### 設定の一括適用（ある画像の設定を、選んだ複数の画像へ）

同じ調子を何十枚にも当て直すときは、1 枚で決めた設定を、ほかの画像へまとめて写せます。

1. 適用元にする画像を開く（設定は保存済みであること。バージョンを開いていれば、そのバージョンが適用元）。
2. 画像一覧パネルで適用先を選ぶ: サムネイルを **Ctrl（⌘）+クリック**で個別に、**Shift+クリック**で範囲を選択。パネル上部の
   「すべて選択」は、いまの絞り込み（名前・「未設定」など）の結果を全部選びます。「選択を解除」で解けます。ふつうのクリックは、従来どおり画像を開きます。
3. 選択中に出る **「いまの画像の設定を、選択した N 枚へ適用…」** を押し、ダイアログで次を選んで「適用」。

| 項目 | 内容 |
|---|---|
| 適用する範囲 | 入力（自動レベル・平滑化）/ 線画 / 人物のトーン / 背景のトーン / 部分ごとのトーン（部分名ごと）/ 透かし / 出力。既定は全部オン。画像倍率（`unit`）だけは既定でオフ（画像の大きさで自動のため） |
| 適用先のバージョン | 既定のバージョン / いま開いているのと同じ名前のバージョン（無ければ、その画像の既定のバージョンを複製して作る）/ 新しい名前のバージョンを作ってそこへ（元の設定を残したいとき） |
| 層の消しゴムを対応づけられない画像にも適用する | 既定はオフ（下の説明） |
| 適用後に書き出す | オンにすると、適用した画像だけを続けて書き出す（一括書き出しと同じ仕組み） |

- **消しゴム・ペン・部分マスクの手直しは写しません**（画像ごとの物のため）。
- 部分ごとのトーンは、**適用先の画像にその部分のマスクがあるときだけ**写します（無い部分は飛ばし、結果の一覧に出ます）。
  適用元で「人物と同じ設定」のままの部分は、適用先でも人物に連動させます（適用先が持っている設定は消しません）。
- 層の消しゴムは層の id で結び付いています。人物・背景・部分のトーンを写すと層が入れ替わる（層の id は適用元と同じになる）ので、
  **適用先に層の消しゴムがあって、適用後の層と id で対応づけられない画像は飛ばして**、一覧に出します（同じ適用元から前に適用した画像は、
  id が同じなので対応づけられ、消しゴムはそのまま残ります）。「…にも適用する」をオンにすると、その層の消しゴムを捨てて適用します
  （捨てた消しゴムもバックアップに残り、取り消しで戻ります）。ベタ・線画・「すべて」の消しゴムとペンは、どの場合もそのままです。
- 書き換えはサーバが設定ファイルに対して行います（各画像を開きません）。**適用先ごとに、前の設定を世代バックアップへ退避してから**書きます。
  結果（適用 / 飛ばし（理由つき）/ 失敗）がダイアログに並び、**「いまの適用を取り消す」**で、その 1 回の適用をまとめて元に戻せます
  （適用が作ったバージョンは、バージョンごと消えます。取り消すと、適用のあとでその画像に加えた変更も、適用の直前まで戻ります。戻す前の状態も退避されます）。
  バックアップを無効にしているときは、取り消せません。
- 適用された画像は「書き出しが古い」になり、画像一覧の印が替わります。開いている画面（別のタブを含む）には、設定ファイルの変更として反映されます。
- 画面で選べる適用先は、いまの画像フォルダの中だけです。別のフォルダへは `ctl` で適用します（下）。

```bash
uv run inkdeus ctl apply --from <画像名> --to <画像名…|all|unconfigured|'*.png'> [--scope input,lines,person,background,parts:hair,…]
                         [--from-folder F] [--from-version V] [--to-folder F] [--to-version default|same|new:<名前>] [--export] [--force]
uv run inkdeus ctl apply --undo            # 直前の適用を取り消す（--list で記録の一覧。--undo <番号 or ID> で選ぶ）
uv run inkdeus backup list <プロジェクト> --kind apply                 # サーバを起動していなくても、記録を見られる
uv run inkdeus backup restore <プロジェクト> --kind apply --at <番号>  # 1 回の適用を、まとめて取り消す
```

- `--to` は、画像名（複数可）/ `all`（フォルダの全画像）/ `unconfigured`（設定のまだ無い画像）/ glob。当てはまる画像が無い指定は、何も変えずに非 0 で終わります。
- `--scope` を省くと `unit` 以外の全部。`parts` は適用元にある部分の全部、`parts:<部分名>` で部分を選びます。
- `--from-version` を省くと、適用元をブラウザで開いていればそのバージョン、そうでなければ既定のバージョン。`--to-folder` を省くと適用元と同じフォルダ。
- `--export` は白黒化の画面を開いているブラウザが要ります（適用そのものは、ブラウザなしでできます）。結果は JSON（`applied` / `skipped` / `failed`）。

## データを守る（バックアップ・書き出しと取り込み・付け替え）

### 保存の状態と、保存の取りこぼし対策

- ヘッダ（漫画の画面では素材パネルの「保存の状態」）に、いつも **「保存済み」「保存中…」「未保存の変更あり」「保存に失敗（再試行中）」**
  のどれかが出ます。
- 保存に失敗したとき（サーバを止めた・落ちた）は、変更を画面が持ったまま、間隔を広げながら再試行し、サーバが戻ると保存されます。
  その間は、別の画像・バージョン・フォルダへは移りません（移ると、保存できていない変更が失われるため）。**その画面は閉じないでください。**
- 消しゴム・ペンは、筆を置いた直後（と、筆の取り消し・やり直しの直後）に、変わった所だけを小さくまとめてサーバへ送ります。
  ポインタを離してすぐにタブを閉じても、その筆は残ります。
- 保存していない変更・保存の途中があるときにタブを閉じる・再読み込みすると、ブラウザの確認が出ます。
  タブが隠れた（別のタブへ移った・閉じかけた）ときは、待ち時間を待たずに保存します（漫画の画面の自動保存も同じ）。

### 世代バックアップ（保存のたびに、前の版を残す）

画像ごとの設定（`*.inkdeus.json`）、消しゴムとペン（`*.paint/`）、部分マスクの手直し（`*.maskedit/`）、漫画データ（`manga/*.lz4`。自動保存を含む）、プロジェクトの設定
（`inkdeus.project.toml`）、このプロジェクトのスタイル（`styles.json`）は、**上書き・削除の直前に、いまのファイルが退避されます**。
書き出した PNG・PDF・縮小画像は対象外です（作り直せるため）。

- 置き場は `<out>/.backup/`（プロジェクト単位。`<out>/.backup/@<フォルダ>/<名前>@<バージョン>.inkdeus.json/<時刻>.json` のように、
  保存先の構成をそのまま写します）。全プロジェクト共通の自分用スタイルだけは、設定フォルダの `.backup/` に入ります。
- 同じ内容なら退避しません。直近 10 個は全部残し、それより古い物は「1 時間に 1 個を 24 時間ぶん、1 日に 1 個を 30 日ぶん」だけ残します。
  1 ファイルあたり 200 個、プロジェクト全体で 2GB の上限があり、超えたら古い物から消します。
  `inkdeus.local.toml` の `[backup]`（`enabled` / `keep_recent` / `hourly_hours` / `daily_days` / `max_per_file` / `max_total_mb`）で変えられます。
- **白黒化の画面**: 出力パネルの「以前の状態に戻す…」で、その画像・バージョンの設定と消しゴム・ペンの「戻せる時点」が新しい順に並びます。
  選ぶと、その時点の変更が行われる直前の状態に戻ります。戻す前のいまの状態も残るので、出てくる知らせの「取り消す」で元に戻せます。
- **漫画の画面**: 「プロジェクトから開く」の欄で保存データを選ぶと「以前の版…」が出ます。開くだけで、いまの保存データは変わりません
  （その版を残すには「プロジェクトに保存」）。
- コマンド:

```bash
uv run inkdeus backup list <プロジェクト>                                   # 何が何個あるか
uv run inkdeus backup list <プロジェクト> --name <画像名> [--folder F] [--version V]   # その画像の戻せる時点（番号つき・新しい順）
uv run inkdeus backup restore <プロジェクト> --name <画像名> --at <番号 or 時刻>      # 設定と消しゴム・ペンをまとめて戻す
uv run inkdeus backup restore <プロジェクト> --kind manga --name <保存名> --at 1      # 漫画データ（自動保存は autosave）
uv run inkdeus backup restore <プロジェクト> --kind project --at 1                    # プロジェクトの設定（--kind styles でスタイル）
uv run inkdeus backup prune <プロジェクト>                                  # 間引く（保存のたびにも自動で行われる）
```

  `--kind` は `params`（設定だけ）/ `paint`（消しゴム・ペンだけ）/ `maskedit`（マスクの手直し）/ `manga` / `project` / `styles`、`--at` は `list` の番号（1 がいちばん新しい）か
  時刻（`2026-01-31T12:34` の形。「その時刻の状態」に戻ります）。戻す前のいまの状態も退避されます（取り消し方が表示されます）。
  稼働中のサーバがあれば、戻した中身は開いている画面へ反映されます。
- **壊れたファイル**（0 バイト、JSON として読めない、など）は**上書きしません**。設定ファイルが壊れていた画像を開くと、画面が
  「最新のバックアップから戻す / 既定値で始める」を尋ね、選ぶまでは何も保存しません（`ctl` の `set` / `patch` / `preset` も受け付けません）。
  どの場合も、壊れたファイルは `<名前>.broken-<時刻>` として残ります。書き込みはすべて「一時ファイルへ書いてから改名」で行うので、
  中断や同時の書き込みで 0 バイトや混ざった中身のファイルが残ることはありません。

### プロジェクト全体の書き出しと取り込み

```bash
uv run inkdeus export-project <プロジェクト> -o <ファイル.zip> [--with-exports] [--with-backups] [--with-sources]
uv run inkdeus import-project <ファイル.zip> --name <新しい名前> [--images <dir>] [--masks <dir>]
```

- zip には、設定・消しゴムとペン・部分マスクの手直し・漫画データ・このプロジェクトのスタイルと、目録（`manifest.json`: 中身の一覧と SHA-256、inkdeus の版、
  画像フォルダの名前と枚数）が入ります。**元画像フォルダなどの絶対パスは入りません**（フォルダ名と、zip の中の相対構成だけ）。
  プロジェクトの設定のうち、このPCの場所を指す物（素材ソース `[[assets]]`・フォント `[fonts]`）は持ち出しません。
- 既定では、元画像・マスク・書き出した PNG・PDF・バックアップは含めません。`--with-sources` で元画像・人物マスク・部分マスク、
  `--with-exports` で書き出した PNG・PDF、`--with-backups` で世代バックアップも入ります。
- 取り込みは、目録のハッシュを確かめてから行います（合わない・zip の外を指す名前がある、などは中止して何も残しません）。
  元画像を含まない zip は `--images` で場所を指定します。指定しなければ、プロジェクトは作られ、`inkdeus projects` に
  「元画像の場所が未設定」と出ます（`inkdeus relink` で決めます）。追加の画像フォルダの元画像が無いときは、
  `inkdeus folders add <名前> --name <フォルダ名> --images <dir>` で場所を決めると、そのフォルダの設定がつながります。

### 元画像の場所の付け替え

```bash
uv run inkdeus relink <プロジェクト> [--folder <フォルダ名>] --images <新しいdir> [--masks <dir>] [--parts <dir>] [--force]
```

- 付け替える前に、新しい場所に同じ名前の画像がどれだけあるかを表示します: **一致**（両方にある）/ **不足**（いまの設定・書き出しが
  あるのに、新しい場所に無い）/ **余分**（新しい場所にだけある。新しい画像として出ます）。不足があれば、`--force` 無しでは中止します。
- いまの場所が既に消えていても、保存先に残っている設定・書き出しから「あったはずの画像」を数えます。
- 設定・消しゴムとペン・漫画データは画像名で引かれるので、付け替えたあともそのままつながります（漫画データの中の絵も、そのまま表示されます）。
- 元画像の場所が見つからないプロジェクトも `inkdeus open` で起動でき（画像は 0 枚）、画面の上に
  「元画像の場所が見つかりません（`inkdeus relink …`）」と出ます。付け替えたら、サーバを起動し直してください。

### inkdeus を更新したとき

サーバは、ビルド識別（リポジトリのコミットと `web/` のファイルの要約）と、起動のたびに変わる起動 ID を、`/api/config` とイベントの接続直後に返します。
開いている画面は、読み込んだときと違う版のサーバを見つけると、**「inkdeus が更新されました。再読み込みしてください」** の帯を出します
（自動では再読み込みしません。帯のボタンは、保存していない変更を先に保存してから再読み込みします）。
逆に、画面のファイルの方が新しい（`git pull` などで更新したのに、サーバを起動し直していない）ときは、
**「サーバを再起動してください」** の帯が出ます（再起動するまで、新しい機能の一部は使えません）。白黒化の画面と漫画の画面の両方で働きます。

## 外部からの操作（ctl）

稼働中のサーバには `inkdeus ctl` で外から指示できます。設定を変えると、開いているブラウザにすぐ反映されます
（設定ファイル `<out>/<名前>.inkdeus.json` をエディタで直接書き換えても同じです）。出力は JSON です。

```bash
uv run inkdeus ctl state                                   # 開いている画像・プロジェクト・フォルダ
uv run inkdeus ctl get [--name N]                          # 設定JSON
uv run inkdeus ctl presets                                 # 名前付きスタイルの一覧（組み込みと自分用。origin が出どころ）
uv run inkdeus ctl preset "ハッチ(1)" --region background   # スタイルを領域に適用（person / background / both / 部分名）
uv run inkdeus ctl preset ベタ --region hair                # 部分（部分マスクのある部分）に当てると、その部分だけ別の設定になる
uv run inkdeus ctl set regions.hair.solid.lineKnockout 0.8  # ベタの中の線画を白抜き
uv run inkdeus ctl set regions.background.levels.brightness 0.25
uv run inkdeus ctl patch '{"regions": {"person": {"solid": {"threshold": 0.1}}}}'
uv run inkdeus ctl stats --wait                            # 描画結果の統計（いまの設定に対する物が届くまで待つ）
uv run inkdeus ctl open <画像名> [--version V]             # ブラウザで開く画像（とバージョン）を切り替える
uv run inkdeus ctl export                                  # ブラウザに書き出しを指示（保存先が返る）
uv run inkdeus ctl export-all [--force] [--default-only] [--wait]   # 全画像・全バージョンの書き出しを指示（--status で進み具合、--abort で中止）
uv run inkdeus ctl folders                                 # 画像フォルダの一覧と枚数（current がいま開いているフォルダ）
uv run inkdeus ctl open <画像名> --folder <フォルダ名>     # 別のフォルダの画像を開く
uv run inkdeus ctl versions [--name N]                     # バージョンの一覧
uv run inkdeus ctl version new <V> [--from <元>]           # 設定を複製して新しいバージョンを作る（--from 省略時は既定から）
uv run inkdeus ctl version rename <旧> <新>
uv run inkdeus ctl version delete <V>                      # 設定と PNG を消す
uv run inkdeus ctl style save <名前> --region <領域> [--scope user|project] [--with-levels] [--description "…"]
                                                           # 開いている画像の、その領域の設定を自分用スタイルとして保存
uv run inkdeus ctl style delete <名前> [--scope user|project]   # 削除（rename <旧> <新> で名前の変更）
uv run inkdeus ctl style export <名前> > style.json        # JSON を標準出力へ。import <ファイル> [--scope …] [--overwrite] で取り込む
uv run inkdeus ctl paint list                              # 消しゴム・ペン（人が画面で描いた物）のうち、保存されている対象の一覧
uv run inkdeus ctl paint clear <対象|all-targets>          # 対象の消しゴム（またはペンで描いた物）を消す
uv run inkdeus ctl apply --from <画像名> --to all          # その画像の設定を、ほかの画像へまとめて適用（「設定の一括適用」の節。--undo で取り消し）
```

- `--name` を省くと「いまブラウザで開いている画像」が対象です。
- `get` / `set` / `patch` / `preset` / `stats` / `export` は `--version <名前>` でバージョンを選べます。省くと「いまブラウザで開いているバージョン」
  （`--name` で開いていない画像を指したときは既定のバージョン）が対象です。既定のバージョンを明示するときは `--version ""`。
  `ctl state` の `currentVersion` が、いま開いているバージョンです（既定は `""`）。
- 画像フォルダが複数あるときは、どのコマンドも `--folder <名前>` でフォルダを選べます（既定のフォルダは `default`）。省くと「いまブラウザで開いているフォルダ」が対象です
  （`ctl state` の `currentFolder`）。開いていないフォルダを指すときは `--name` も要ります。`export-all` は `--all-folders` で全フォルダを書き出します。
- 接続先の `--port`（既定 8770）と `--host` は、サブコマンドの前でも後ろでも書けます（`inkdeus ctl --port 8771 state` と `inkdeus ctl state --port 8771` は同じ）。
- `patch` は JSON Merge Patch (RFC 7396) です。配列（`layers`）は丸ごと置換になるので、1層だけ変えるときは `set regions.person.layers.0.width 0.4` のように番号で指します。
- 範囲外の値や未知のキーは非0終了になり、何も変わりません。
- `stats` は黒率・平均の濃さ・ベタや各層の面積率・入力の輝度の分布を、全体／人物／背景ごとに返します（どの設定に対する統計かを示す `rev` つき）。画像を見ずに数値で調整するためのものです。
  部分マスクのある画像では、部分ごとの項目（`output.hair` / `input.hair` など。`linked` = 人物と同じ設定で描いているか）も返します。
  別の設定にした部分は `person` の集計から外れます（`person` = 人物の設定で描かれている所）。
- 自分用スタイルは `ctl preset <名前> --region <領域>` でそのまま当てられます（`ctl presets` の `origin` が `user` = 全プロジェクト共通 /
  `project` = このプロジェクト専用）。`style save` の `--region` は `person` / `background` / 部分名で、`--with-levels` で明るさ補正も含めます。
  `style import` は、`style export` の出力や `styles.json` そのものを読みます（同じ名前があるときは `--overwrite` で上書き）。
- 部分名は、部分マスクの置き場にある名前だけを受け付けます（打ち間違いは非0終了）。`ctl folders` の `partNames` が、そのフォルダの部分名です。
  まだ設定の無い部分へ `set` / `patch` すると、いまの人物の設定を写した項目ができます。`regions.<部分名>.linked` が `true` の間は人物と同じ設定で
  描かれるので、**その部分だけ変えるには `linked` を `false` にします**（`ctl preset … --region <部分名>` は自動で切ります）。
  数値は消しゴム・ペンを反映した最終出力に対する物で、`paint`（`targets` = 描いた物のある対象、`penUsed`）で、手が入っているかが分かります。
- `paint` は `--name` / `--folder` / `--version` で対象を選べます（省くと、いまブラウザで開いている画像・バージョン）。対象は `layer-<層の id>`（id は `ctl get` の `layers[].id`）/
  `solid-person` / `solid-background` / `solid-<部分名>` / `lines` / `all` / `pen` で、`all-targets` は全部です。消すと、開いている画面にもすぐ反映されます（その画面の取り消しの履歴は消えます）。
  描くこと自体は人が画面で行います（`ctl` からは描けません）。
- ブラウザを開いていなくても設定ファイルは更新され、次に開いたとき反映されます（統計と書き出しはブラウザが必要です）。
- `export-all` は白黒化の画面を開いているブラウザが実行します。`--wait` を付けると終わるまで待って件数（書き出し / 飛ばし / 失敗）を返します。
  進み具合は `ctl export-all --status` と `ctl state` の `batch` で見られます。

Claude Code 用のスキル（`.claude/skills/inkdeus/SKILL.md`）に、起動から「言葉での依頼 → ctl での調整 → 統計での確認」までの手順をまとめてあります。

## 漫画の構成（Manga Editor Desu! との連携）

書き出した白黒の画像を、コマ割り・吹き出し・文字入れのできる漫画エディタへそのまま持ち込んで、ページに組めます。

漫画エディタは inkdeus の一部ではありません。**new-sankaku 氏による別プロジェクト「Manga Editor Desu! Pro Edition」**
（<https://github.com/new-sankaku/manga-editor-desu>、GPL-3.0）を使います。inkdeus のリポジトリには含まれておらず、
次のコマンドで利用者のPCへ取得します（inkdeus はこのプロジェクトの公式の配布元ではありません）。

```bash
uv run inkdeus manga install            # 取得（git が必要。~/.cache/inkdeus/manga-editor-desu/<コミット>/ に置く）
uv run inkdeus manga status             # 導入済みの版と場所、当てた差分
uv run inkdeus open <プロジェクト>      # 起動して、ブラウザで http://127.0.0.1:8770/manga/ を開く
```

- 取得する版は、動作を確かめてあるコミット `04e0cf3de1f3677682f6d1831f2713db70e441ba` に固定しています（`--ref <コミット>` で変更可。別の版では連携が動かないことがあります）。
- 取得済みのクローンが手元にあれば `--from <クローンのフォルダ>` でネットワークなしに導入できます（クローンが指定の版でないときはエラー。`--allow-mismatch` でそのまま使う）。
- キャッシュの場所は環境変数 `INKDEUS_CACHE` で変えられます。未導入のまま `/manga/` を開くと、導入方法の案内が出ます。
- inkdeus は `/manga/` で配信するときに、ページ（index.html）だけを次のように書き換えます（取得したファイル自体は変えません）:
  **Google Analytics（アクセス解析）と service worker を無効にし、inkdeus の連携スクリプト（`web/manga-bridge/`）を差し込みます。**
- 漫画エディタのフォントや一部の UI（アイコンなど）は外部（Google Fonts、cdnjs、unpkg）から読み込まれるため、オフラインではそれらが欠けます。

### 素材パネル

`/manga/` の画面の右端に、inkdeus の「素材」パネルが出ます（「素材」のタブで開閉）。

- タブは素材の「ソース」です。既定で **元画像**（プロジェクトの元画像）と **白黒**（inkdeus で書き出した PNG）があります。名前での絞り込みもできます。
  プロジェクトに画像フォルダが複数あるときは、タブの下の「フォルダ」で、元画像・白黒のタブが見るフォルダを切り替えます（タブはフォルダの数だけ増えません）。
  白黒の調整の反映・「白黒を調整」・元画像と白黒版の差し替えは、その絵が属するフォルダの中で働きます。
- サムネイルを押すと、**選択中のコマ**へその画像が入ります（コマの形に切り抜かれます）。コマは、キャンバス上のコマかレイヤー一覧のコマを押して選びます。サムネイルをコマへドラッグしても入れられます。
- コマへ渡す画像の大きさを選べます（長辺 1024 / 2048 / 4096 / 原寸。既定 2048）。画像は漫画データに埋め込まず、inkdeus のサーバ上の場所（URL）で持つので、漫画データは軽いままです。
  そのため、この漫画データは **inkdeus のサーバ経由（`/manga/`）で、同じプロジェクトを開いているとき**にだけ画像が表示されます。元の画像を動かしたり消したりすると表示できなくなります。
- 「プロジェクトに保存」「プロジェクトから開く」で、全ページをまとめた漫画データ（漫画エディタの保存形式 `.lz4`）をプロジェクトの `manga/` フォルダに保存・読み込みします。
  変更から 30 秒後（「自動保存」の横で 10 / 30 / 60 / 120 秒から選べます）と、ページを切り替えたとき・タブを離れたときには `manga/autosave.lz4` へ自動保存されます
  （自動保存にも世代バックアップが効きます）。次に開いたとき「前回の続きを開きますか」と聞かれ、**名前を付けて保存した最後の物と自動保存のうち、新しい方**が
  選んであります（どちらも、更新時刻とページ数つきで選べます）。漫画エディタ自身の保存・読み込み（ファイルのダウンロード）もそのまま使えます。
- **漫画エディタ自身の自動保存は止めてあります。** 漫画エディタは、単体では 60 秒ごとにブラウザの中（IndexedDB）へ全ページを保存し、次に開いたとき
  「Recover Auto-save」を全画面で尋ねます。inkdeus 経由（`/manga/`）では上の自動保存と二重になるので、これを止めて、保存先をプロジェクトの
  `manga/autosave.lz4` に一本化しています（漫画エディタの設定欄の「自動保存」は押せなくなります）。
  止める前の版を使っていてブラウザの中にデータが残っているときは、初回だけパネルの中で
  「漫画エディタ側に、以前の自動保存が残っています。**開く / 無視する（次回から尋ねない）/ 消す**」と尋ねます（勝手には消しません。
  「開く」は漫画エディタの復元の画面で中身を確かめてから開き、開いた物は「プロジェクトに保存」するまでプロジェクトには入りません）。
  漫画エディタ側の自動保存をそのまま使いたいときは、`/manga/` のページで開発者ツールから
  `localStorage.setItem('inkdeus.manga.upstreamAutosave', 'keep')` として読み込み直します（パネルに
  「漫画エディタ側の自動保存が有効です」と出ます。戻すには、その項目を消します）。
- 「このページを書き出す」「全ページを書き出す」で、ページの PNG を `manga/pages/<保存名>/001.png …` に保存します（大きさは漫画エディタの原稿サイズと DPI の設定で決まります）。
- プロジェクトなし（`inkdeus run`）で起動したときの保存先は `<出力フォルダ>/manga/` です。

### コマ割り（長方形のコマを、行と列で組む）

素材パネルの「コマ割り」の欄で、ページを「行と列に分かれた長方形の集まり」として組めます。境界線・コマの間隔・結合といった、
漫画エディタ単体には無い「コマどうしの関係」を inkdeus 側で持ち、そこから漫画エディタのコマの形を決めます。

- **格子を作る**: 「行ごとのコマ数」に `2,1,3`（上の行から 2 コマ・1 コマ・3 コマ）のように書いて「格子を作る」。よく使う形は下のボタンから。
  いまのページに作ります。既にコマがあれば確かめたうえで置き換え、**コマに入っている画像は、読む順（上から下、右から左）に新しいコマへ引き継ぎます**
  （コマが足りなければ最後のコマへ。引き継いだ画像は、新しいコマを覆う大きさで中央に置き直します）。
- **コマ割りモード**（ボタンで入り、ESC・「モード解除」・もう一度ボタンで抜ける）:
  - 行・列の**境界線をドラッグ**すると、両側のコマが同時に伸縮します（間隔は保たれ、最小の大きさより小さくはなりません）。
    Shift を押している間は、ページの 1/2・1/3・1/4 と、ほかの境界の位置に吸い付きます。
  - 境界線の**両端の丸をドラッグ**すると、その端だけが動いて境界が斜めになり、両側のコマが台形になります。ダブルクリックでまっすぐに戻ります。
  - コマをクリックで選択（Shift+クリックで 2 つ目）。選ぶと欄に「縦に割る」「横に割る」「結合」「削除」「断ち切り」が出ます。
    Alt+クリックで、押した位置で左右に（Alt+Shift+クリックで上下に）割ります。ボタンを Alt+クリックすると、次に押した位置で割ります。
  - 選んだコマの**頂点や辺をドラッグ**すると、そのコマは「連動から外れた」状態になり、形を自由に変えられます
    （辺をつかめるのは、連動から外れたコマです。最初は頂点から）。連動から外れたコマは、間隔のスライダーや境界線のドラッグでは動きません。
    「連動に戻す」で元の長方形に戻ります。
- **割る・結合・削除**: 割ると、中の画像は「画像の中心がある側」に残り、位置と大きさは変わりません。結合できるのは同じ行（列）で隣り合う 2 つで、
  画像は両方残ります。削除すると隣のコマが比率に応じて埋め、中の画像は「残す（コマなしの自由な画像になる）／一緒に消す」を選べます。
- **間隔と余白**: 「間隔（縦）」「間隔（横）」「余白（上下）」「余白（左右）」（個別の値も指定可）を変えると、ページ全体のコマが計算し直されます。
  値はどれも**ページの短辺に対する割合（%）**です。
- **断ち切り**: 選んだコマの、ページの端に接している辺ごとに「端まで伸ばす」を切り替えます。
- **中の画像**（コマの形が変わったとき）: 「相対位置を保って動かす」（既定。コマの外接矩形の変化に合わせて、画像の中心の相対位置と、
  コマに対する大きさ = 面積の比の平方根の等倍率を保つ）／「動かさない」／「覆うように入れ直す」。
- **いまのコマを取り込む**: 漫画エディタのひな形やナイフで作った既存のコマから、行と列の構成を推定して取り込みます。対象は、ほぼ軸に平行な長方形で、
  行・列に分けられる配置だけです（長方形でないコマは対象外として残り、その数が表示されます）。取り込むと、間隔が揃うようコマがわずかに動きます。
- どの操作も**取り消し 1 回で戻ります**。レイアウトは漫画データに入るので、ページの切り替え・保存と読み込みのあとも続けて操作できます。
- **吹き出しと文字は動きません**（漫画エディタの作りとして、吹き出し・文字はコマに紐づいていないため）。コマの形を変えたあとは、必要なら手で置き直してください。
- 漫画エディタ側の操作でレイアウトのコマを動かす・頂点を編集すると、そのコマは連動から外れます。Delete キーやナイフでコマを消すと、
  その場所は空いたまま残ります（コマ割りモードでその場所を選んで「削除」すると、隣のコマが埋めます。ナイフで切った後は「いまのコマを取り込む」で組み直せます）。

### PDF にまとめる（印刷・入稿向け）

「保存と書き出し」の「PDF を書き出す…」で、全ページ（または範囲）を 1 つの PDF にまとめて `manga/pdf/<出力名>.pdf` に保存します。
終わると、パネルに保存先と「開く」のリンクが出ます。

| 項目 | 内容 |
|---|---|
| 対象のページ | 空欄 = 全ページ。範囲は `1-8,10` のように書く |
| 仕上がりサイズ | B5（182×257mm）/ A5（148×210）/ A4（210×297）/ B6（128×182）/ カスタム（mm）。「ページの縦横比に合わせる」を入れると、選んだサイズに余白なしで収まる最大の大きさになる |
| 解像度 | 350 / 600 / 1200 dpi / カスタム（72〜2400）。白黒の線画は 600 dpi 以上がおすすめ |
| 塗り足し | なし / 3mm / 5mm。塗り足しありのとき、PDF のページは「仕上がり＋塗り足し」の大きさになり、絵はその枠いっぱいに中央で置かれる（絵の外周が塗り足しに入る）。トンボは描かない。PDF の TrimBox（仕上がり）と BleedBox（塗り足し込み）を設定する |
| はめ込み方 | 収める（余白は白）/ 埋める（はみ出しは切る） |
| 色 | グレースケール（8bit）/ 白黒2値（1bit。しきい値つき）/ そのまま（RGB） |
| 綴じ方向 | 右綴じ / 左綴じ（PDF の `/ViewerPreferences /Direction` に入る。対応したビューアの見開き表示の向きが変わる） |
| 開いたときの表示 | 1ページずつ / 見開き（表紙だけ単独）/ 見開き |

- 画像は可逆（Flate）で埋め込みます（JPEG にはしません）。ページは、必要な画素数（(仕上がり＋塗り足し×2)×dpi）にちょうど足りる倍率で書き出されるので、
  漫画エディタ側の原稿サイズ・DPI の設定には影響しません（設定も書き換えません）。
- ページの絵と用紙の向きが違うとき（横長のページなど）は、用紙の縦横を入れ替えます。
- 各ページは 1 枚ずつサーバへ送られ、PDF はサーバ側で作られます（数十ページでもブラウザのメモリに溜めません）。途中で「中止」できます。
- ブラウザが 1 枚の画像として作れる大きさ（長辺 16384 px ほど）を超える設定では、作れる最大で書き出してからサーバ側で拡大します（その旨が表示されます）。
- CMYK への変換やトンボが必要な入稿先には、この PDF をそのままは使えません（印刷所の入稿仕様を確かめてください）。

### 白黒の調整をその場で反映する（2つのタブ）

白黒化の画面（`/`）と漫画の画面（`/manga/`）を**別々のタブで開いておく**と、`/` で調整した結果が `/manga/` にすぐ反映されます。

1. `/manga/` の素材パネルで、サムネイルの「調整」（またはキャンバスで画像を選んで「白黒を調整」）を押す。
   白黒化の画面がその画像を開いた状態で別のタブに出ます（2回目以降は同じタブが使い回されます）。
2. 白黒化の画面で設定を変える。少し置くと PNG が自動で書き出されます（「変更を自動で書き出す」がオンのとき。`ctl` での変更でも同じ）。
3. `/manga/` のタブでは、**いま開いているページでその白黒版を使っている絵がすべて新しい画像に替わります**
   （位置・大きさ・切り抜き・コマとの紐づけはそのまま。取り消しの履歴には積まれません）。ほかのページは、開いたときに最新の白黒版が出ます。

- 素材パネルの「元画像」タブの「入れる画像」で、コマへ入れる物を選べます: 「白黒版があれば白黒」（既定）/「常に元画像」。
- 「白黒」タブでは、同じ元画像のバージョンが横に並びます（各サムネイルにバージョン名。最初からある物は「既定」）。それぞれ別の素材としてコマへ入れられ、
  白黒化の画面で調整したときは、**そのバージョンを使っている絵だけ**が替わります。
- キャンバスで白黒版の絵を選ぶと「バージョン: <名前>」と、同じ元画像の別バージョンへ切り替えるボタンが出ます（位置・見た目の大きさ・切り抜き・コマとの紐づけはそのまま。取り消せます）。
  「白黒を調整」はそのバージョンを開いた白黒化の画面を出し、「新しいバージョンを作って調整」は、いま置いてあるバージョンを複製して、置いてある絵を新しいバージョンへ切り替えてから開きます。
- 「入れる画像: 白黒版があれば白黒」は、既定のバージョンを入れます。
- バージョンを削除すると、それを使っている絵は既定のバージョン（まだ無ければ元画像）へ切り替わり、その旨が表示されます。
  名前を変えたときは、**いま開いているページ**の絵だけが新しい名前へ付け替わります。ほかのページや保存済みの漫画データに残った古い名前は、
  開いたときに「見つからないバージョン」として既定のバージョンへ切り替わります（名前の変更は、使っているページを開いた状態で行うか、変更後に各ページで選び直してください）。
- 選択中の絵は「白黒版に差し替え」「元画像に戻す」で切り替えられます（こちらは取り消せます）。白黒版がまだ無い画像は、「調整」で開けば自動で書き出されます。
- 「白黒版ができたら元画像を置き換える」（既定オフ）をオンにすると、元画像のまま置いてある絵が、白黒版が書き出された時点で白黒版に切り替わります。
- 素材パネルは左端をドラッグして幅を変えられます（ダブルクリックで既定の幅。幅は次回も復元）。画面が狭いときは「⧉」で、漫画エディタの画面を押しのけず重ねて表示できます。

### ローカルフォント

このPCにあるフォントファイル（.ttf / .otf など）を、漫画の文字で使えるようにできます。`inkdeus.local.toml`（全プロジェクト共通）か
プロジェクトの `inkdeus.project.toml` に書きます（両方あれば合算）。

```toml
[fonts]
dirs = ["<フォントのあるフォルダ>"]            # 複数可
include = ["Example-Mincho.ttf", "ExampleSerif-*.otf"]   # ファイル名の glob。省略すると dirs 内の全フォント
[fonts.names]                                  # 任意: ファイル名 → 表示名
"Example-Mincho.ttf" = "例の明朝"
```

- `uv run inkdeus fonts list [--project <名前>]` で、見つかったフォントと表示名を確かめられます。表示名はフォントファイルに書かれた名前（日本語名があれば日本語名）で、
  同じ名前が複数あるときはウェイト名を足して区別します。
- `/manga/` のフォント選択の先頭に「inkdeus」の見出しで並びます。本体は使ったときに初めて読み込まれます（選択の一覧には名前だけが出て、その書体での見本は出ません）。
  設定を書き足したときは、素材パネルの「フォント」の「↻」で読み直します。
- フォントファイルは inkdeus のリポジトリには含まれません。利用者が自分で用意した物を、自分のPCで使うだけです。
- 各フォントのライセンス（作品への利用・配布の可否など）は、利用者が確かめてください。
- 漫画データにはフォントの名前と取得先（inkdeus のサーバ上の場所）だけが記録されます。別のPCや漫画エディタ単体で開くと、そのフォントは「見つからない」扱いになります。

### 素材ソースの追加（擬音など）

画像の入ったフォルダを、素材のソースとしてプロジェクトに登録できます。

```bash
uv run inkdeus assets add <プロジェクト> --name 擬音 --path <フォルダ> --mode free --recursive
uv run inkdeus assets list <プロジェクト>
uv run inkdeus assets remove <プロジェクト> --name 擬音
```

- `--mode panel`（既定）はコマにはめ込む画像、`--mode free` は透過 PNG の擬音など、コマにはめずにページ上へ自由に置く素材です（押すとページ幅の 25% ほどの大きさで置かれます）。
- `--recursive` でサブフォルダも含め、フォルダ名で見出し分けします。
- 登録内容はプロジェクトの `inkdeus.project.toml` の `[[assets]]`（`name` / `path` / `mode` / `recursive`）に書かれます。
  `inkdeus.local.toml` に同じ形の `[[assets]]` を書くと、全プロジェクト共通のソースになります。稼働中に登録したときは、パネルの「↻」で一覧を読み直すと反映されます。

## 透かし

透かしは任意の機能で、既定ではオフです。「透かし」の「透かしを入れる」スイッチ（設定JSON の `watermark.enabled`）をオンにすると、
プレビューと書き出し画像に文字の透かしが入ります。文字列・位置・大きさ・濃さを変えられます
（文字列が空のときは `inkdeus` になり、大きさ・濃さには描画が壊れないための最小値があります）。

以前の版にあった起動引数 `--owner`、環境変数 `INKDEUS_OWNER`、`inkdeus.local.toml` の `owner` は廃止しました。指定してあってもエラーにはならず、無視されます。

## 設定JSON

```json
{"version": 2, "unit": null, "input": {}, "lines": {},
 "regions": {"person": {"levels": {}, "solid": {}, "layers": []},
             "background": {"mode": "keep", "linked": true, "levels": {}, "solid": {}, "layers": []},
             "hair": {"linked": false, "levels": {}, "solid": {}, "layers": []}},
 "watermark": {}, "output": {}}
```

欠けたキーは既定値で補い、未知のキーや使えない値は警告を表示します。旧形式（version 1: トップレベルに `solid` / `layers` / `background`）は読み込み時に移行します。
キー・既定値・値域・名前付きスタイルの定義の元は `web/schema.json` です（ブラウザとサーバの両方がこれを読みます）。

| キー | 既定 | 内容 |
| --- | --- | --- |
| `unit` | `null` | 基準px に掛ける倍率。`null` = 画像の幅 / 1280 |
| `input.autoLevel` | `true` | 輝度の 1〜99 パーセンタイルでのレベル補正 |
| `input.smoothRadius` / `smoothStrength` | `2.0` / `0.1` | トーン分け用の平滑化の半径（基準px）/ 強さ。0 で無効 |
| `lines.enabled` / `strength` | `true` / `1.0` | 線画（XDoG）を描く / 濃さ |
| `lines.sigma` | `0.8` | ガウスの σ（基準px） |
| `lines.tau` / `epsilon` / `phi` | `0.98` / `-0.01` / `100` | XDoG の τ・しきい値 ε・鋭さ φ |
| `regions.<領域>.levels.brightness` / `contrast` / `gamma` | `0` / `1` / `1` | その領域のトーン分けに使う輝度の補正（-1〜1 / 0〜3 / 0.2〜5） |
| `regions.<領域>.solid.enabled` / `threshold` / `soft` | `true` / `0.15` / `0` | ベタ。しきい値未満を黒に（しきい値 1 は全面ベタ）。`soft` は境界のぼかし幅 |
| `regions.<領域>.solid.lineKnockout` | `0` | ベタの中の線画を白抜きにする強さ（0〜1。ベタで塗られた所の線画を白で描く） |
| `regions.<部分名>.linked` | `true` | `true` の間、その部分は人物と同じ levels / solid / layers で描く。`false` で、この項目の設定が有効 |
| `regions.<領域>.layers[].id` | （自動） | 層の名前（英小文字と数字の短い乱数。消しゴムのマスクがどの層の物かを決める）。作成・複製のときに振られ、並べ替えでは変わらない。無ければ読み込み時に補って保存する |
| `regions.<領域>.layers[].type` / `enabled` | `"hatch"` / `true` | 層の種類（現在は `hatch` のみ）/ 表示 |
| `layers[].threshold` / `soft` | `0.5` / `0.03` | 輝度がこれ未満の所に描く / 境界のぼかし幅（線を細らせて表現） |
| `layers[].angle` | `45` | 線の角度（°。0=水平、45=右上がり、90=垂直） |
| `layers[].spacing` / `width` | `2.0` / `0.5` | 線の間隔 / 太さ（基準px） |
| `layers[].widthByDarkness` | `0` | 0=太さ一定、1=しきい値付近は細く暗いほど太く |
| `layers[].opacity` / `phase` | `1.0` / `0` | 濃さ / 位相ずらし（間隔に対する割合） |
| `regions.background.mode` | `"keep"` | `keep`=層で描く / `white`=白 / `lines`=線だけ（マスクが必要） |
| `regions.background.linked` | `true` | `true` の間、背景は人物と同じ levels / solid / layers で描く |
| `regions.background.grow` | `3.0` | マスクの広げ（正）/ 縮め（負）（基準px） |
| `regions.background.silhouetteWidth` | `1.5` | `white` のときのシルエット線の太さ（基準px） |
| `regions.background.lineStrength` | `0.6` | `lines` のときの背景の線の濃さ |
| `watermark.enabled` | `false` | 透かしを入れる |
| `watermark.text` / `position` | `"inkdeus"` / `"br"` | 文字列 / 位置（`br` `bl` `tr` `tl` `center` `tile`） |
| `watermark.size` / `opacity` | `14` / `0.35` | 大きさ（基準px、最小 4）/ 濃さ（最小 0.05） |
| `output.binary` | `false` | 純2値（0 と 255 だけ） |

`<領域>` は `person`（人物。マスクの内側。マスクが無ければ全体）と `background`（背景）、それに部分名（`hair` など。部分マスクのある部分）。
部分の項目（`regions.<部分名>` = `linked` / `levels` / `solid` / `layers`）は、書かれたときだけ持ちます（無ければ、その部分は人物と同じ設定）。
層は領域ごとに最大 8。
層の `id` は書かなくてかまいません（`ctl patch` で層を丸ごと書き直すときに省くと、同じ位置にあった層の id を引き継ぎます）。
既定は「重ねがけ4段」（しきい値 0.72 / 0.52 / 0.38 / 0.27、角度 45° / 135° / 0° / 90°）とベタ 0.15 です。

## 上流（Manga Editor Desu!）を改変している箇所

漫画エディタは GPL-3.0 の別プロジェクトで、inkdeus のリポジトリにはそのファイルを 1 つも含めていません。inkdeus が加えている変更は次の 2 種類で、
どちらも利用者の手元（キャッシュ）と配信時にだけ行われます。GPL-3.0 の趣旨に沿って、変更点をここに明示します。

**1. 配信時の書き換え**（キャッシュ上のファイルは変えません。`src/inkdeus/manga.py` の `REMOVALS`）:
index.html から Google Analytics の読み込みと送信、service worker の登録、PWA の manifest を外し、inkdeus の連携スクリプト
（`web/manga-bridge/bridge.css` / `bridge.js`）を差し込みます。連携スクリプトは実行時に、次の箇所へ手を入れます（上流のファイルは変えません）:
保存される属性の一覧（`commonProperties`）に `ikLayout` / `ikCell` を足す、`fabric.Canvas.prototype.loadFromJSON` と
`ModeManager.clearAll` を包む（レイアウトの復元と、コマ割りモードの解除のため）、`fabric.Image.prototype.srcFromAttribute` を有効にする、
フォントの一覧（`fmFontData`）に「inkdeus」の分類を足す、**漫画エディタ自身の自動保存を止める**（`AutoSaveManager` の公開されている入口
`init` / `start` / `restart` / `setEnabled` / `setInterval` / `save` / `checkRecovery` を、漫画エディタの起動処理が呼ぶ前に「何もしない物」へ差し替える。
ブラウザの中への定期保存と、起動時の復元の確認が出なくなる。設定欄の `autoSaveCheckbox` / `autoSaveInterval` は押せなくする。
ブラウザの中に残っているデータは消さない。差分ファイルは使っていないので、差分を当てていない導入でも同じように働く）。

**2. 上流のコードへの差分**（`patches/manga-editor-desu/<コミット>/*.patch`。`inkdeus manga install` が、取得した作業ツリーへ番号順に `git apply` で当てます）:

| 差分 | 変えるファイル | 内容 |
|---|---|---|
| `0001-get-object-by-guid` | `js/core/util/fabric-util.js` | `getObjectByGUID(searchGuid)` が、引数ではなく `setGUID()` の書く暗黙のグローバル変数 `guid` と比べていた不具合を直す（コマを消したとき、中の画像の切り抜きが外れないことがある） |
| `0002-template-to-current-page` | `js/sidebar/speechBubble/speech-bubble-effect.js` | コマのひな形を押したときの処理の先頭に、連携スクリプトの入口（`window.inkdeusTemplateHook`）を足す。既定の動き（新しいページを作る）は変わらない。「コマ割り」の欄の「ひな形を押したら: いまのページのコマを置き換える」を選んだときだけ、新しいページを作らずに、いまのページのコマを置き換える |
| `0003-knife-keeps-image-place` | `js/sidebar/panel/knife/knife-split-engine.js` | ナイフでコマを切ったとき、中の画像を「大きいほうのコマの中央に入れ直す」のをやめ、位置と大きさを保ったまま、画像の中心がある側のコマへ入れる（**既定の挙動が変わります**。「コマ割り」の欄の「ナイフで切ったら: 中央に入れ直す（元の挙動）」で戻せます） |

- 各差分は、当たったことを `window.__inkdeusPatches` に自分の名前を足して知らせます（連携スクリプトはこれを見て、対応する設定を出します）。
- 1 つでも当たらない差分があれば、当てた分をすべて取り消して**差分なしの状態**で導入します（その旨と理由が `inkdeus manga status` に出ます）。
  差分が無くても、素材パネル・保存・書き出し・PDF・コマ割りツールは動きます（使えないのは、上の表の 3 点だけです）。
- `inkdeus manga install --no-patches` で、差分を当てずに導入できます。`inkdeus manga status [--json]` で「当てた差分」「未適用の差分」を確かめられます。
- 差分の仕組みが入る前の版で導入したキャッシュには差分が当たっていません。その場合、サーバの起動時のログと `/manga/` のパネルに案内が出ます
  （自動では当てません）。**`uv run inkdeus manga install` をやり直すと当たります**（やり直したら `/manga/` を再読み込みしてください。サーバの再起動は不要です）。

## 開発

```bash
uv sync
uv run playwright install chromium     # 描画テスト用（初回だけ）
uv run pytest                          # 全件（並列）
```

描画テストはヘッドレス Chromium で合成画像を描き、出力画素を数値で検証します。テスト画像はすべてスクリプトで生成します。

### テストの回し方（手元の素早い確認 → push の前に全件）

| いつ | コマンド | 目安（16 コアの PC） |
|---|---|---|
| 変更に関係する範囲だけ | `scripts/test-changed`（基準は `origin/main`。`scripts/test-changed HEAD~1` のように変えられる） | 数秒〜数分 |
| ブラウザを使わない物だけ | `uv run pytest -m server` | 約 20 秒 |
| 漫画エディタの結合テストを除く | `uv run pytest -m "not manga"` | 約 4 分 |
| 重い物（5120×3840 の画像など）を除く | `uv run pytest -m "not slow"` | 全件より 1 分ほど短い |
| **全件（push の前）** | `INKDEUS_MANGA_SRC=<クローン> uv run pytest` | 約 7 分 |
| 直列（不具合を追うとき） | `uv run pytest -n 0` | 約 20 分 |

- 既定で**並列**（pytest-xdist）です。ワーカー数は CPU のコア数の 1/4（2〜6。ソフトウェア描画の WebGL が 1 ページで CPU を 2〜3 個使うため、
  コア数ぶんは立てません）。`-n 6` か環境変数 `INKDEUS_TEST_WORKERS=6` で変えられ、`-n 0` で直列になります。
- 同じファイルのテストは同じワーカーで、書いた順に回します（`--dist loadgroup`。漫画の画面やサーバをファイル単位で共有し、
  前のテストの結果を使うテストがあるため）。`tests/test_manga_layout.py` だけは、差分あり・なしを別のワーカーへ分けます。
- 印（`-m` で選ぶ）: `ui` = ブラウザを使う / `server` = 使わない（どちらも自動で付く）/ `manga` = 実物の漫画エディタが要る / `slow` = 1 本で何十秒もかかる。
- `scripts/test-changed [基準] [--list] [-- pytest の引数…]` は、基準からの差分（コミット済み・未コミット・追跡前のファイル）を見て、
  スクリプトの先頭の対応表（`RULES`）でテストを選びます。対応表に無いファイルや、どこにでも効くファイル（`src/inkdeus/server.py`、
  `tests/conftest.py` など）が 1 つでもあれば全件を回します。`--list` は、選んだ結果を表示するだけです。
- テストのブラウザは、OS に標準で入っている場所のフォント（`/usr/share/fonts` など）だけを見ます。漫画エディタは起動のたびに 200 個ほどの
  フォント名を描いて調べるので、利用者のフォント設定に遅い置き場（別 OS のフォントフォルダなど）が入っていると、漫画の画面を開くたびに
  十数秒かかるためです（結果が、その PC のフォントに左右されないようにする意味もあります）。`INKDEUS_TEST_SYSTEM_FONTS=1` で、利用者のフォント設定をそのまま使います。
- 結合テストの待ちの上限（既定 180 秒）は `INKDEUS_TEST_WAIT_MS` で短くできます（不具合を追うとき）。

ブラウザを使うテストが落ちると、その時点の証拠（開いている全ページのコンソール・ページエラー・通信の失敗、スクリーンショット、
画面の状態、サーバのリクエストとイベントの列。どれも時刻つき）が、テストごとのフォルダに残ります（場所は失敗の表示の末尾に出ます）。
保存先は環境変数 `INKDEUS_TEST_EVIDENCE`（既定は一時フォルダの `inkdeus-test-evidence/`）、`INKDEUS_TEST_EVIDENCE_ALWAYS=1` で
通ったテストの分も残します。

漫画の構成の結合テスト（`tests/test_manga_bridge.py`、`test_manga_layout.py`、`test_manga_pdf_ui.py` など）は実物の漫画エディタが必要です。固定している版のクローンの場所を
環境変数 `INKDEUS_MANGA_SRC` で渡します（無ければ skip されます）。
なお、上流の漫画エディタは単体では 60 秒ごとにブラウザの中（IndexedDB）へ自動保存し、次に開いたページで復元するかを全画面で尋ねますが、
inkdeus 経由では連携スクリプトがこれを止めます（「素材パネル」の節）。止まること・残っているデータの扱い・止めない設定のときの挙動は
`tests/test_manga_autosave.py` が確かめます。

```bash
git clone https://github.com/new-sankaku/manga-editor-desu <どこか>
git -C <どこか> checkout 04e0cf3de1f3677682f6d1831f2713db70e441ba
INKDEUS_MANGA_SRC=<どこか> uv run pytest tests/test_manga_bridge.py
```

コマ割りの計算（`web/manga-bridge/layout-core.js`）は漫画エディタにも画面にも依存しない関数だけなので、`tests/test_layout_core.py` が
空のページの上で直接呼んで確かめます（上流のクローンは不要）。コマ割りツールの結合テストは、差分を当てた導入と当てていない導入の両方で動かします。
